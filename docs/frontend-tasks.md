# A 同学任务：前端页面与联调

状态基线：2026-09-25，`frontend` 目前只有占位文件，尚未创建 React 工程。后端基础接口已完成，详见 [后端接口清单](backend-handoff.md)。

## 1. 负责范围与优先级

使用 React + TypeScript + Vite，实现可实际操作的学生端、教师端。先跑通现有后端，不先开发 AI 聊天、小游戏、运动打卡或复杂动画。

### P0：先交付可用的业务闭环

| 页面/功能 | 必须完成的行为 | 对接接口 |
| --- | --- | --- |
| 登录页 | 输入用户名和密码，显示失败原因，登录后查询身份 | `POST /api/auth/login`、`GET /api/auth/me` |
| 任务列表/详情 | 显示标题和说明，分页，处理加载中和空列表 | `GET /api/tasks`、`GET /api/tasks/{task_id}` |
| 教师发布任务 | 输入标题和描述，发布成功后刷新列表 | `POST /api/tasks` |
| 学生提交成果 | 选择任务、填写文字、阻止重复点击，显示提交结果 | `POST /api/submissions` |
| 我的成果 | 显示当前状态及反馈；只有退回记录出现重交入口 | `GET /api/submissions/mine` |
| 修改重交 | 回填成果内容，提交后状态恢复待审核 | `PUT /api/submissions/{submission_id}` |
| 教师审核 | 查询待审核成果，查看内容，填写反馈并通过/退回 | `GET /api/reviews/pending`、`POST /api/reviews/{submission_id}` |

教师待审核列表当前只提供 `student_id`，不提供姓名。先显示学生编号，不要编造姓名或调用不存在的用户列表接口。教师需要任务标题时，可按 `task_id` 查询已有任务详情并缓存。

### P1：与 C 完成积分联调

- 积分余额、积分流水、奖励列表与兑换确认界面。
- 兑换前确认消耗；处理余额不足、库存不足、重复点击。
- 积分接口目前不存在。先与 C 确认路径、字段、权限和错误码，再接入。
- 如使用模拟数据开发界面，要明显标注“演示数据”，且保留与真实接口切换的边界；不能把模拟余额当成已完成的后端功能。

## 2. 推荐开发顺序

1. 初始化前端工程，明确启动、构建命令并提交锁文件。
2. 建立统一请求封装和 TypeScript 数据类型，先调通登录和当前用户查询。
3. 完成任务列表、教师发布、学生成果提交。
4. 完成学生记录、教师审核、退回重交。
5. 和 B 跑通双身份的整条流程，再对接 C 的积分功能。

建议组织：`src/api/` 放请求封装，`src/types/` 放接口类型，`src/pages/` 放页面，`src/components/` 放通用组件，登录态放统一上下文或状态模块。具体目录可以调整，不必为小项目引入复杂状态库。

## 3. 登录、请求和页面规则

- 登录使用 JSON；成功后携带 `Authorization: Bearer TOKEN_VALUE` 调用受保护接口。
- 必须通过 `/api/auth/me` 的角色决定页面入口，不能仅凭用户自行选择的“教师/学生”按钮授权。
- 前端隐藏按钮只是体验控制，实际权限由后端判断，仍要处理 403。
- Token 按敏感凭据处理，不放 URL、不打印到日志、不写入仓库。基础版可先保存在内存，刷新后重新登录；持久化登录方案另行确认。
- 退出登录目前只清除前端保存的 Token；后端没有撤销 Token 或刷新 Token 的接口。
- 401 引导重新登录；409 刷新数据并提示冲突；422 展示字段错误；网络故障保留编辑内容并提供重试。
- `detail` 可能为字符串或数组，请求失败时不能一律调用字符串方法。
- 接口返回列表是数组，没有 `items` 或 `total`。先使用上一页/下一页，不虚构总页数；末页可能需要处理一次空结果。
- 默认分页每页 20，`limit` 最大 100，`offset` 非负。取得记录后使用真实 ID，不把数组下标当成记录编号。
- 成果、反馈最多 2000 字符；任务标题最多 100。去掉首尾空格后为空的内容应在前端提示，后端也会校验。
- 审核请求使用 `decision`，成果响应使用 `status`；学生重交只发 `content`。
- 请求执行期间禁用重复点击；不要对提交、审核、兑换请求做不加区分的自动重试。

## 4. 本地联调：先解决跨域

后端当前默认地址为 `http://127.0.0.1:8000`，没有安装 CORS 中间件。推荐前端开发服务器代理 `/api` 到该地址，浏览器代码使用同源 `/api` 路径。

如果选择让浏览器直接请求后端，则由 B 根据实际前端来源配置 CORS，允许所需 HTTP 方法与 `Authorization`、`Content-Type` 请求头。`localhost` 与 `127.0.0.1` 是不同来源，端口也要一致。不能为了省事开放所有来源再把它当成生产配置。

Vite 开发代理不自动适用于构建后的静态页面；交付时还要明确静态文件服务与 API 转发方案，不要双击 HTML 当作部署方式。跨机器联调时，`127.0.0.1` 指向各自电脑，不是同学电脑，需要另行协商局域网地址和服务监听设置。

## 5. 验收清单

- [ ] 学生、教师分别登录，入口与权限正确。
- [ ] 教师发布的任务能被学生看到。
- [ ] 学生提交后显示待审核，重复提交显示提示而非成功。
- [ ] 教师退回时必须填写反馈；学生能看到反馈并重交。
- [ ] 重交保持同一个成果编号；教师通过后学生看到已通过。
- [ ] 已通过成果不出现编辑入口；过期登录态能恢复到登录页。
- [ ] 空列表、加载中、400/401/403/404/409/422/500、网络断开均有适当反馈。
- [ ] 在第二个学生账号下看不到第一个学生的记录；该测试账号由团队测试准备，不擅自开放注册。
- [ ] 积分接口未完成时不显示虚假的真实奖励到账提示。
- [ ] 手机/窄屏可完成关键操作，按钮和输入框不被遮挡。
- [ ] 交付可重复执行的安装、启动、构建说明，且不包含密码或 Token。
